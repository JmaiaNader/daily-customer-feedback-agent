# Daily Customer Feedback Analysis Agent

نسخة تعليمية تجريبية لتحليل Customer Surveys يوميًا باستخدام Python وStreamlit وOllama، مع إرسال التقرير إلى Gmail.

## محتويات المشروع

- `app.py`: واجهة Streamlit لاختيار مصدر البيانات (Google Drive افتراضيًا أو رفع ملف من الحاسوب للاختبار)، وتحليل فترة يدويًا.
- `agent_core.py`: قراءة Excel، حساب CSAT، مقارنة الموظفين، تحليل التعليقات بواسطة Ollama، حفظ التقرير وإرسال Gmail.
- `scheduler_service.py`: طبقة الجدولة الجديدة، وحالة التشغيل ومعالجة التداخل والأخطاء.
- `run_daily.py`: نقطة تشغيل قديمة لعملية أمس فقط، وتقرأ Google Drive فقط ولا تستخدم ملف الحاسوب أو الملف التجريبي.
- `README_DEPLOYMENT.md`: خطوات النشر على Streamlit Community Cloud وحدود الجدولة هناك.
- `data/sample_surveys.xlsx`: بيانات تجريبية مصطنعة في Worksheet اسمها `rowdata`.
- `reports/`: التقارير التي يتم حفظها.
- `logs/`: سجل التشغيل وحالة آخر يوم تم إرساله.

## متطلبات التشغيل

- Windows / macOS / Linux
- Python 3.11+
- اتصال إنترنت لقراءة Google Drive عبر رابط تنزيل، ولإرسال Gmail.
- Ollama مثبت محليًا إذا أردت تحليل التعليقات بالـ LLM.
- Gmail App Password لإرسال الرسائل.

## 1) التثبيت على Windows

افتح PowerShell داخل مجلد المشروع:

```powershell
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

إذا منع PowerShell تفعيل البيئة الافتراضية، يمكنك تشغيل Python من البيئة مباشرة، أو استخدام Command Prompt وتفعيل:
`.\.venv\Scripts\activate.bat`

## 2) تشغيل Ollama

ثبّت Ollama من الموقع الرسمي، ثم في Terminal:

```powershell
ollama pull gemma3:4b
ollama list
```

تأكد أن Ollama يعمل. عادة تكون الخدمة متاحة محليًا على `http://localhost:11434`.

إذا كان النموذج بطيئًا جدًا أو ذاكرة الجهاز غير كافية، جرّب نموذجًا أصغر متاحًا في Ollama، ثم غيّر `OLLAMA_MODEL` في `.env` وداخل الواجهة.

## 3) إعداد Gmail

1. فعّل التحقق بخطوتين لحساب Google.
2. أنشئ App Password من إعدادات حساب Google إذا كان حسابك مؤهلًا لذلك.
3. انسخ `.env.example` إلى ملف باسم `.env`.
4. اكتب بريد المرسل، App Password، وبريد المستلم في `.env`.
5. لا ترسل `.env` لأي شخص ولا تضعه في Git.

## 4) تشغيل الواجهة

```powershell
streamlit run app.py
```

ستفتح واجهة Streamlit في المتصفح. اختر **Google Drive (default file)** لتحميل ملف Google Drive الافتراضي، أو **Laptop (test upload)** لرفع ملف محلي للتجربة فقط، ثم اضغط **Load Excel**. من تبويب **Scheduler** يمكنك ضبط الفترة (أمس/أحدث يوم متاح/فترة مخصصة)، ووقت التشغيل، وعدد مرات التشغيل، وقائمة المستلمين المحفوظة. اختر تاريخ البداية والنهاية ثم **Analyze selected date range**. ستظهر معاينة التقرير قبل الإرسال، ويمكنك تنزيل Markdown أو JSON. في تبويب **Data preview** تستطيع تصفية بيانات `rowdata` حسب التاريخ والفئة والموظف ودرجة CSAT ثم تصديرها إلى CSV أو Excel.

## 5) اختبار Google Drive

ضع ملف Excel الرسمي في Google Drive واضبط `DRIVE_DOWNLOAD_URL` في `.env` على رابط الملف الذي يسمح بالتنزيل. يظهر Google Drive كمصدر افتراضي في الواجهة. يمكنك اختيار Laptop ورفع `sample_surveys.xlsx` لاختبار التحليل يدويًا؛ هذا لا يغيّر مصدر الـ Scheduler.

**مهم:** طريقة رابط المشاركة تعمل فقط عندما يسمح الرابط بالتنزيل. للملفات الخاصة، يمكن ضبط `GOOGLE_SERVICE_ACCOUNT_JSON` في Streamlit Secrets، ثم مشاركة الملف مع بريد حساب الخدمة بصلاحية Viewer. لا تجعل بيانات العملاء متاحة للعامة لتسهيل الاختبار؛ استخدم البيانات الاصطناعية الموجودة هنا.

## 6) اختبار الجدولة تلقائيًا

قبل الجدولة، تأكد أن `DRIVE_DOWNLOAD_URL` في `.env` يشير إلى ملف Google Drive الرسمي الذي يسمح بالتنزيل. يقرأ `run_daily.py` Google Drive فقط في كل تشغيل، ولا يرجع إلى ملف الحاسوب أو `DATA_FILE` إذا فشل اتصال Drive. يفحص بيانات **أمس فقط**؛ إذا لم توجد صفوف لذلك التاريخ فلن يرسل بريدًا. وإذا نجح الإرسال لذلك التاريخ، فلن يرسله مرة أخرى. الروابط الخاصة تحتاج إعداد OAuth/API مناسبًا.

شغّل اختبارًا يدويًا أولًا:

```powershell
python run_daily.py
```

إذا نجح، افتح Windows Task Scheduler:
1. اختر **Create Basic Task**.
2. الاسم: `Daily Customer Feedback Agent`.
3. Trigger: Daily.
4. Action: Start a program.
5. Program/script: المسار الكامل إلى `.venv\Scripts\python.exe`.
6. Add arguments: المسار الكامل إلى `run_daily.py`.
7. Start in: مجلد المشروع.
8. في إعدادات المهمة، اختر تشغيلها عند الوقت المناسب، وتحقق من سجل `logs/scheduler.log`.

**شرط:** الحاسوب يجب أن يكون شغالًا وغير نائم وقت تنفيذ المهمة. لن تعمل المهمة على حاسوب مطفأ. بعد النشر على Server، يمكن أن يعمل الحاسوب الشخصي وهو مغلق.

### محاكاة كل 5 دقائق
في Task Scheduler، استخدم Trigger يوميًا ثم Advanced settings → Repeat task every 5 minutes لمدة ساعة للاختبار. أوقف التكرار بعد الاختبار. انتبه أن `run_daily.py` يتجنب إعادة إرسال نفس تاريخ البيانات بعد نجاحه.

## 7) ملاحظات مهمة عن المنطق الحالي

- التحليل اليدوي في الواجهة يقبل فترة من تاريخ البداية إلى تاريخ النهاية، شاملًا اليومين.
- المجدول في `run_daily.py` يفحص أمس فقط. إذا لم توجد بيانات أمس، يسجل ذلك ولا يرسل بريدًا. وإذا سبق نجاح الإرسال لأمس، يتجاوز التشغيل المكرر.
- إذا أضيفت بيانات متأخرة إلى تاريخ سبق إرساله، فالنسخة الحالية لا تعيد معالجة ذلك التاريخ تلقائيًا. يمكن تطويرها لاحقًا باستخدام معرفات الصفوف أو نافذة إعادة معالجة.
- متوسطات الموظفين تُعرض مع عدد الاستبيانات. لا تستنتج أداء الموظف من عينة صغيرة أو من التعليقات وحدها.
- النموذج المحلي يرسل نصوص التعليقات إلى Ollama المحلي، ولا يحتاج إلى API مدفوع من مزود LLM خارجي.
- التقرير يحتوي على فرضيات وأفعال مقترحة، لا على إثبات سببي نهائي.
- لا توجد قاعدة بيانات في هذه النسخة؛ حالة آخر تاريخ مرسل محفوظة في `logs/state.json`. عند نشر متعدد النسخ على Server، نحتاج تخزين حالة أكثر موثوقية.
- لا تضع بيانات عملاء حقيقية قبل مراجعة سياسة الخصوصية والموافقة الداخلية.

## 8) الأعمدة الموجودة في ملف Excel

`SurveyID`, `SurveyDate`, `StaffID`, `StaffName`, `Category`, `CustomerName`, `CustomerComment`, `CSATScore`, `FlightNumber`, `Airport`, `Channel`, `Language`

> ملاحظة: أسماء العملاء في ملف البيانات التجريبي مُولّدة لأغراض ورشة العمل فقط وليست بيانات عملاء حقيقية. يدعم التحميل ملفات Google Drive القديمة التي لا تحتوي على `CustomerName` مؤقتًا، إلى حين تحديث المخطط المباشر.

CSATScore يجب أن يكون رقمًا من 1 إلى 5. التواريخ بصيغة `YYYY-MM-DD`. الملف المرفق يحتوي على بيانات اصطناعية للتجربة فقط.


### Google Sheets

يمكن وضع رابط Google Sheets في `DRIVE_DOWNLOAD_URL`؛ يحوّله التطبيق إلى تنزيل XLSX للملف كاملًا ثم يقرأ ورقة العمل المحددة (افتراضيًا `rowdata`). يجب أن يكون الملف متاحًا لحساب التشغيل عبر إعدادات المشاركة. إذا كان الملف خاصًا بالشركة، فالرابط وحده لا يكفي ويلزم إعداد Google Drive API/OAuth أو Service Account.

## 7) النشر على Streamlit Community Cloud

راجع `README_DEPLOYMENT.md`. خزّن `GMAIL_ADDRESS` و`GMAIL_APP_PASSWORD` و`DRIVE_DOWNLOAD_URL` وأي بيانات اعتماد Google Drive داخل **App settings → Secrets**، ولا ترفعها إلى Git. الجدولة داخل عملية Streamlit غير مضمونة عند النوم أو إعادة التشغيل؛ اترك `ENABLE_BACKGROUND_SCHEDULER = false` في Cloud واستخدم عاملًا مجدولًا خارجيًا مع تخزين دائم للإعدادات وسجل التشغيل عند الحاجة إلى إرسال تلقائي موثوق.


## لوحة الإدارة: قوائم البريد والمساعد التحليلي

- شغّل `app.py` للوحة الإدارة، واحتفظ بـ `feedback_app.py` لواجهة المشاركة العامة فقط.
- تُقيَّد لوحة الإدارة من إعدادات المشاركة الخاصة في Streamlit Community Cloud. لا توجد كلمة مرور إضافية داخل التطبيق.
- تبويب `Chat & recipients` يجيب عن أسئلة شائعة حول عدد الاستبيانات، متوسط CSAT، الدرجات المنخفضة والإيجابية، الفئات، الموظفين، أحدث التعليقات والاتجاهات اليومية باستخدام حسابات Python من البيانات الفعلية.
- طلب إعداد أو إرسال تقرير يولّد معاينة أولاً. لن يُرسل البريد إلا بعد اختيار قائمة المستلمين، مراجعة التقرير، وتأكيد الإرسال يدوياً.
- أنشئ جدول Google خاصاً منفصلاً لقوائم البريد، وشاركه مع حساب الخدمة كـ Editor. ضع رابطه في `RECIPIENTS_SPREADSHEET_URL` واسم التبويب في `RECIPIENTS_SHEET_NAME=recipient_lists`. لا تخزن عناوين البريد في ملف البيانات العام.
